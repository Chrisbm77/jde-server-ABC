## What each guide covers (paraphrased summary — verify specifics against the live guide)

**Procurement Management (eoapr).** Core buy-side flow: enter purchase order (P4310/P43101) → print PO/receiver → receive goods (P4312) → voucher match (P4314) → pay (via AP). Every PO detail line carries a line type that tells the system how to treat it (e.g. "S" for stock items, which both replenishes Inventory and drives GL/AP cost). Voucher creation method depends on the receiving process: manual match verifying invoice against receipt, batch mode against existing receipts, or Voucher Match Automation (VMA) — which uses the same AAI logic as manual match but auto-creates standard or logged vouchers, refining candidate records from the F0411Z1 interoperability table. Cost-side AAI tables cover PO entry, receipts/voucher match, variances, tax liabilities, receipt routing, landed costs, and zero-balance adjustments. Country-specific and industry-specific variants (Apparel via Matrix Entry, Project Manufacturing with production-number pegging) reuse the same core PO→receipt→voucher-match programs.

*VMA automation rules (this is the detail people actually get stuck on):* an automation rule (assigned per F0411Z1 record, or defaulted from the supplier master's Purchasing 2 tab if not specified) determines the matching logic — no valid rule on either the record or the supplier means VMA errors out rather than matching. **Rules 01-06 match against receipts** (Purchase Order Receiver File F43121): 01 = basic exact match; 02-05 add exact-match-to-PO-line, multi-receipt-line matching, and rounding tolerance (05 specifically applies a configurable rounding tolerance via P43221); 06 = exact match of an invoice to multiple receipt lines across multiple POs. **Rules 07-09 (Release 9.2 Update) match against PO lines directly, without requiring a receipt** (Purchase Order Detail File F4311 instead of F43121) — 07 = exact invoice-line-to-PO-line match; 08 = same with a standard tolerance (via P4322, tolerance rules by function type) applied when the order amount exceeds the invoice; 09 = exact match of invoice-line amounts to one or more PO lines. Each rule number runs on its own dedicated UBE (R4304016 for rule 01, R4304020 for 02-05, R4304021 for 06, R4304017 for 07-09), all invoked by the Voucher Match Automation Driver (R4304010), which also controls via a processing option whether the run creates standard vouchers or logged vouchers. This is a good example of a topic where the reference summary gives the shape but a live fetch of "Automation Rules" and "Common Terms" topic pages under eoapr is worth doing for anything rule-number-specific.

**Subcontract Management (eoasu).** Manages contracts, commitments, and progress payments for subcontractors tied to jobs (works closely with Job Cost — see topic `ba-project-management`). A contract carries a committed amount; as work progresses you enter progress payments (vouchers) drawn against that commitment, with support for partial payments, joint payees/alternate payees, and change orders that adjust the committed amount with a full audit trail. Retainage is the standout concept: a percentage of each payment is withheld until a specified release date (common in construction), tracked via AAI PCNBRT and released later as its own manual voucher — retainage can be applied to the whole voucher or line-by-line, and a non-billable-retainage flag on line-type constants controls whether nonbillable accounts get the same automated treatment. Reporting includes contract/commitment analysis (budget vs. contract vs. invoiced vs. paid vs. retained vs. remaining) and an AIA-style (American Institute of Architects G702-equivalent) Application for Payment report.

**Buyer Workspace and Supplier Self-Service (eoasr, "SRMC" — Supplier Relationship Management Collaboration).** Gives buyers a consolidated workspace (orders, suppliers, inventory) and gives suppliers self-service visibility into their own POs. Setup includes PO acknowledgement and change-approval rules — order activity rules, tolerance rules (how much a supplier can change price/date before it needs buyer re-approval), date tolerances, and a buyer distribution list for routing. The related SRM portlet surfaces configurable alerts (e.g. all events at a given status) that link back into Operational Sourcing's buyer/bidder workbenches.

**Requisition Self-Service (eoars).** Puts everyday purchasing (office supplies, etc.) in employees' hands via a Shopping Cart, with a Direct Connect feature that can route employees to an approved supplier's website and bring their selections back into an EnterpriseOne requisition. Requisitions carry a user-defined commodity code (hierarchical categorization) for later spend analysis, and route through configurable approval workflow (up to six levels) via the Work Center. Buyers consolidate approved requisitions into purchase orders using either a batch program or the interactive Requisition Expeditor (R43E060), which also merges requisitions going to the same supplier for pricing leverage before the PO is created.

**Operational Sourcing (eoaos).** Manages RFI/RFP competitive-bid events. The Sourcing Portal gives buyers the Event Workbench (create/publish/analyze/award events) and Bidder Workbench (respond to events); bidders see their own Bidder Workbench plus an RFx registration program. Same SRM-portlet alerting pattern as Buyer Workspace applies here for tracking event status.

**How these fit together with AP/Financials:** a PO's receipt-to-voucher path is procurement's territory, but the vouchers it creates post through the same AP constants/AAIs/tax-explanation-code logic in topic `ba-financials` — a three-way-match question (e.g. sales tax on a stock purchase) genuinely needs both guides.
